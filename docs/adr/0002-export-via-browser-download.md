# エクスポートはブラウザのダウンロード、インポートは passui が行う

バックアップ先（ゲストのディレクトリ）にファイルを置く仕組みをやめ、エクスポートファイルをホストのブラウザにダウンロードさせることにしました。戻すときは、エクスポートファイルをブラウザからアップロードし、passui が空のゲストにストアとストアの鍵を戻します（インポート）。以前は「[バックアップファイルを置く場所](https://github.com/backpaper0/passui/issues/60)」で、ダウンロードを退けていました。passui から保存できたかを知れず、置き場所がブラウザの設定に左右されるためです。しかし、ゲスト上のバックアップ先からクラウドストレージへ送る手段を整えるのが、思ったより面倒でした。また、シークレットを追加・削除する頻度は低く、手でダウンロードしてクラウドストレージへ保存する手間はそれほどでもありません。そこで、保存できたかを passui が知れないことを受け入れ、置き場所は利用者に任せることにしました。

## Considered Options

- **バックアップ先に置く方式のまま、インポートだけを足す**: ゲストからクラウドへ送る手段を整える手間が残るため、採りませんでした。
- **インポートではストアだけを戻し、鍵は手作業のまま**: 復元のつらさの大半は鍵の扱いにあり、利点がほとんど残らないため、採りませんでした。

## Consequences

- `PASSUI_BACKUP_DIR` はなくなります。残っていても、知らない `PASSUI_*` として警告されるだけです。
- passui はインポートのときに限り、ストアと gpg-agent の鍵ファイルの場所（`private-keys-v1.d`）に書き込みます。インポートを受け付けるのは空のゲスト（ストアがないか空で、同じ keygrip の `.key` がない）のときだけで、マージも上書きもしません。
- パスフレーズは扱わないため、インポート後に復号できるかは passui からは確かめません。利用者がターミナルで解錠して確かめます。
- 途中で失敗したら、passui が置いた `.key` とストアを消します。`gpg --import` で取り込んだ公開鍵と ownertrust は残します。
- エクスポートファイルの `README.txt` には、passui を使えないときのために、手作業で戻す手順を残します。
